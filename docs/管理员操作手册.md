## 1. 登录与进入后台

### 1.1 默认管理员账户

项目已通过 seeder 预置一个开发用管理员账户：

| 字段 | 值 |
|------|-----|
| 邮箱 | `admin@example.com` |
| 密码 | `admin123` |
| 姓名 | `Administrator` |
| 角色 | `admin` |

> ⚠️ **安全警告**：这是测试密码，**正式上线前务必修改**（见 [第 12 节](#12-个人资料管理)），否则任何人都能登录后台。

### 1.2 登录步骤

1. 启动服务后，在浏览器访问首页：`http://localhost:8000`（或你部署的域名）
2. 点击页面右上角 **登录** 链接，或直接访问 `http://localhost:8000/login`
3. 输入管理员邮箱和密码，点击 **登录**
4. 登录成功后，手动访问后台地址：`http://localhost:8000/admin/dashboard`

> 说明：本项目没有从用户端自动跳转到后台的逻辑。管理员登录后需手动在地址栏输入 `/admin/dashboard` 进入后台。普通用户（role=user）即使访问该地址也会被中间件拦截。

### 1.3 重新创建管理员（开发环境）

若忘记管理员密码且无法登录，可在项目根目录执行：

```bash
php artisan db:seed --class=AdminUserSeeder
```

这会按上述默认值重新创建/覆盖管理员账户。

## 3. 商品上架完整工作流

> 路径：侧边栏 → 商品 → 添加商品
> URL：`/admin/dashboard/products/add`

商品上架分**两步**：先创建商品本体，再为商品添加订阅套餐（价格方案）。本项目是"数字商品商店"，商品通过"订阅（Subscription）"来定价，一个商品可对应多个订阅套餐（如 1 个月 / 3 个月 / 1 年）。

### 3.1 第一步：创建商品

在页面上方的"添加新产品"表单中填写：

| 字段 | 说明 | 是否必填 |
|------|------|---------|
| 商品名称 (Product Name) | 商品名，会自动生成 URL slug | 是 |
| 完整描述 (Full description) | 商品详情描述，纯文本 | 是 |
| 图片 (Images) | 可多选上传，支持常见图片格式 | 是 |
| 分类 (Category) | 从已有分类中下拉选择 | 是 |
| 状态 (Status) | `启用` / `禁用`，控制商品是否在前台显示 | 是 |
| 库存 (Stock) | 库存数量，填数字；为 0 时前台显示"缺货" | 是 |
| 限时抢购？(Flash Sale ?) | 勾选后商品会出现在前台"限时抢购"区块 | 否 |

填写完成后点击 **提交商品 (Submit Item)**。

- 成功：页面顶部显示绿色提示"商品创建成功！"
- 失败：显示红色提示"出错了！"

### 3.2 第二步：添加订阅套餐（定价）

商品创建成功后，**同一页面下方**会自动出现"添加订阅 - [商品名]"表单（商品名显示为黄色文字）：

| 字段 | 说明 | 是否必填 |
|------|------|---------|
| 常规价格 (Regular Price) | 原价，数字 | 是 |
| 特价 (Sale Price) | 折扣价，数字，可不填 | 否 |
| 订阅名称 (Subscription Name) | 套餐名，如"1 个月"、"1 年" | 是 |

点击 **提交订阅 (Submit Subscription)** 即可为该商品添加一个价格套餐。

> 💡 **可重复添加多个订阅**：每次提交后表单会清空，可继续为同一商品添加更多套餐（如"1 个月 $5"、"3 个月 $12"、"1 年 $40"）。这些套餐都会显示在商品详情页供用户选择。

### 3.3 上架流程小结

```
添加分类（若没有）→ 添加品牌（可选）→ 添加商品 → 添加订阅套餐 → 完成
```

> ⚠️ **重要**：如果只创建了商品但没添加任何订阅套餐，商品在前台将没有价格、无法被购买。务必为每个商品至少添加一个订阅。

## 4. 商品列表与编辑

> 路径：侧边栏 → 商品 → 全部商品
> URL：`/admin/dashboard/products`

### 4.1 商品列表

列表展示所有已创建商品，每行包含：

| 列 | 内容 |
|----|------|
| 商品名称 | 带首图缩略图 + 商品名 |
| 名称与常规价格 | 该商品下所有订阅的"名称 : $常规价格" |
| 名称与特价 | 该商品下所有订阅的"名称 : $特价" |
| 状态 | 绿色"启用" / 红色"禁用"徽章 |
| 库存 | 数字；为 0 时显示黄色"缺货"徽章 |
| 操作 | 查看 / 编辑 / 删除 三个图标按钮 |

列表顶部有分类和状态筛选下拉框（注：当前为静态占位，筛选功能未完全实现）。

### 4.2 编辑商品

点击操作列的 ✏️ **编辑** 图标，进入"更新商品"页面（`/admin/dashboard/products/update/{id}`）：

**可修改字段**：
- 商品名称、完整描述、分类、状态、库存、限时抢购
- 图片：可上传新图（多选）；现有图片每张右上角有 ❌ 按钮，点击可删除单张图片

**下方订阅管理区**：
- 表格列出该商品已有的所有订阅套餐（名称、常规价、特价、删除按钮）
- 可在下方表单继续添加新订阅套餐

修改后点击 **提交商品 (Submit Item)** 保存。

### 4.3 删除商品

点击操作列的 🗑️ **删除** 图标即可删除商品（会直接删除，无二次确认弹窗，操作需谨慎）。

## 7. 支付方式配置

> 路径：侧边栏 → 设置 → 支付设置
> URL：`/admin/dashboard/settings/payment`

本项目采用**线下/手动支付**模式：管理员配置收款账户信息（如 bKash、Nagad、银行转账等），用户结账时选择支付方式并手动转账，填写交易流水号提交订单，管理员再人工核实。

### 7.1 添加支付方式

在页面上方表单填写：

| 字段 | 说明 | 是否必填 | 示例 |
|------|------|---------|------|
| 账号 (Account Number) | 收款账号/手机号 | 是 | `+8801700000000` |
| 账户机构名称 (Account Org. Name) | 支付渠道名称 | 是 | `Bkash` / `Nagad` / `银行转账` |
| 备注 (Note) | 给用户的转账说明 | 是 | `请转账/充值到这个个人账户...` |

点击 **添加设置 (Add Setting)** 保存。

### 7.2 管理已有支付方式

页面下方表格列出所有已添加的支付方式，每行可：
- 👁️ 查看（仅占位，无实际跳转）
- ✏️ 编辑：点击后该方式的数据会回填到上方表单，修改后点"添加设置"即更新（按钮文案未变，但实际执行更新）
- 🗑️ 删除：直接删除该支付方式

### 7.3 支付方式如何生效

配置好的支付方式会出现在**用户端结账页**（`/checkout`）的"支付方式"下拉选择中。用户选择一种方式后，会看到你填写的账号和备注，按说明转账后在订单中填写交易流水号。

> 💡 建议至少配置一种支付方式，否则用户结账时无法选择支付方式。

## 8. 通用设置

> 路径：侧边栏 → 设置 → 通用设置
> URL：`/admin/dashboard/settings`

这是网站全局配置，影响前台所有页面。表单字段如下：

### 8.1 基础信息

| 字段 | 说明 | 是否必填 |
|------|------|---------|
| 电话号码 (Phone Number) | 联系电话，显示在前台页脚 | 是（数字） |
| 地址 (Address) | 公司/店铺地址 | 是 |
| 网站名称 (Website Name) | 站点名，显示在后台侧边栏和前台 | 是 |
| 邮箱 (Email) | 联系邮箱 | 是（合法邮箱格式） |

### 8.2 品牌资源

| 字段 | 说明 | 是否必填 | 限制 |
|------|------|---------|------|
| Logo | 网站 Logo 图片 | 否 | jpeg/png/jpg/gif/svg，≤2MB |
| Favicon | 浏览器标签页图标 | 否 | 仅 png，≤1MB |

上传新图时会自动删除旧图。当前已有图片会在字段下方缩略图预览。

### 8.3 地图与货币

| 字段 | 说明 | 是否必填 |
|------|------|---------|
| 地图嵌入链接 (Map Iframe Link) | Google Maps 的 iframe src 链接 | 是 |
| 货币符号 (Currency Logo) | 价格前缀符号，如 `$`、`¥`、`৳` | 是 |

### 8.4 自定义 HTML（高级）

| 字段 | 说明 |
|------|------|
| 自定义 head 元素 | 会注入到页面 `<head>`，可放 meta 标签等 |
| 自定义 script 元素 | 会注入到页面，可放统计代码（如 Google Analytics）等 |

### 8.5 政策条款（富文本）

以下三个字段使用 Summernote 富文本编辑器，支持格式化排版：

| 字段 | 说明 | 对应前台页面 |
|------|------|------------|
| 配送政策 (Delivery Policy) | 配送说明条款 | `/delivery-returns` |
| 退货政策 (Return Policy) | 退货说明条款 | `/delivery-returns` |
| 隐私政策 (Privacy Policy) | 隐私条款 | `/privacy-policy` |

填写完成后点击 **保存设置 (Save Setting)**。

> 说明：通用设置是"单例"配置——若数据库中已有设置则更新，没有则创建。首次配置和后续修改都走同一表单。

## 11. 订单管理与发货

### 11.1 订单列表

> 路径：侧边栏 → 订单 → 全部订单
> URL：`/admin/dashboard/orders`

列表展示所有订单：

| 列 | 说明 |
|----|------|
| 订单编号 (Order ID) | 系统自增 ID |
| 买家姓名 (Buyer Name) | 下单用户名 |
| 总金额 (Total Amount) | 订单总价 |
| 交易流水号 (TrX ID) | 用户填写的转账流水号 |
| 支付方式 (Payment Method) | 用户选择的支付方式 |
| 支付账号 (Payment Number) | 用户付款用的账号 |
| 下单时间 (Ordered On) | 订单创建时间 |
| 状态 (Status) | 彩色徽章：蓝色=已下单、黄色=处理中、绿色=已发货、红色=已取消 |
| 操作 | 👁️ 查看详情 |

### 11.2 订单详情与发货

点击 👁️ 进入订单详情页（`/admin/dashboard/orders/details/{id}`）：

**左侧 - 买家信息**：
- 买家姓名、邮箱、电话
- 支付方式、支付账号、交易流水号

> 💡 **核实付款**：根据这里的支付方式和交易流水号，到对应支付平台核实用户是否真的转账了。

**右侧 - 订单商品**：
- 列出每个商品的"商品名 - 订阅套餐名"及购买数量

**下方 - 发货操作**：

1. **发货邮件标题 (Delivery Mail Title)**：填写将发给买家的邮件标题
2. **发货详情 (Delivery Details)**：在富文本编辑器中填写要交付给买家的内容（如账号密码、使用说明等）
   > 示例：`Netflix 账号 1：邮箱 example@gmail.com，密码 000000，请勿与他人分享凭据，此为 1 屏账号。`
3. 点击 **发送商品到邮箱 (Send Product to Mail)**：
   - 系统会通过邮件将"发货详情"发送到买家邮箱
   - 订单状态自动改为 `已发货 (delivered)`
   - 成功后跳回订单列表并显示"商品已发货。"

**下方 - 订单状态手动修改**：

也可单独修改订单状态（不发货，仅改状态）：
- 下拉选择：已下单 / 处理中 / 已发货 / 已取消
- 点击 **保存状态 (Save Status)**

### 11.3 订单处理工作流小结

```
用户下单（状态=ordered）
   ↓
管理员在订单列表查看详情
   ↓
根据"交易流水号"到支付平台核实收款
   ↓
收款确认 → 改状态为"处理中"（可选）
   ↓
在"发货详情"填写交付内容（账号/密码/链接等）
   ↓
点击"发送商品到邮箱" → 邮件发出 + 状态自动改为"已发货"
   ↓
完成
```

> ⚠️ 发货功能依赖邮件配置（`.env` 中的 `MAIL_*` 配置）。若未配置邮件，发货会失败。开发环境下可能不会真正发出邮件。

## 14. 常见问题与注意事项

### Q1：商品上传后在前台看不到？
检查以下几点：
1. 商品**状态**是否设为"启用"
2. 商品是否分配了**分类**
3. 商品是否至少添加了一个**订阅套餐**（无订阅的商品无价格，无法展示）
4. 库存是否为 0（为 0 会显示"缺货"但仍可见）

### Q2：用户下单后我如何知道？
目前系统**没有订单通知**功能。管理员需定期访问 `/admin/dashboard/orders` 查看新订单。

### Q3：发货邮件发不出去？
检查 `.env` 文件中的邮件配置：
```
MAIL_MAILER=smtp
MAIL_HOST=...
MAIL_PORT=...
MAIL_USERNAME=...
MAIL_PASSWORD=...
MAIL_FROM_ADDRESS=...
```
开发环境可先用 `MAIL_MAILER=log` 测试，邮件内容会写入 `storage/logs/laravel.log`。

### Q4：图片上传后前台显示 broken image？
需确保 `storage` 软链接已创建。在项目根目录执行：
```bash
php artisan storage:link
```
或访问一次 `http://你的域名/tool-links/link-storage`（项目内置的路由）。

### Q5：删除商品/分类/品牌会删除关联图片吗？
- 删除**商品图片**（编辑页点 ❌）：会删除图片文件
- 删除**商品**：会删除商品记录，但其图片文件**不会自动删除**（需手动清理 `storage/app/public/products/`）
- 删除**分类/品牌**：同上，记录删除但图片文件残留

### Q6：如何让商品出现在"限时抢购"区块？
在添加或编辑商品时勾选 **限时抢购？(Flash Sale ?)** 复选框即可。该商品会出现在前台首页的"限时抢购"区块。

### Q7：支付方式编辑后按钮文案还是"添加设置"？
这是正常的——编辑和新增共用同一表单和按钮，点击"添加设置"时系统会自动判断是更新还是新建，无需担心。

### Q8：订单状态徽章显示英文？
订单状态值（ordered/processing/delivered/cancelled）直接来自数据库，当前在列表中显示英文原文。订单详情页的状态下拉框已汉化。如需列表徽章也汉化，需修改 `all-orders-component.blade.php` 中的状态显示逻辑。
